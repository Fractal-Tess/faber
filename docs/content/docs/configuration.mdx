# Configuration

Faber can be configured through environment variables. This document describes all available configuration options.

## Environment Variables

| Variable | Type | Default | Description |
|----------|------|---------|-------------|
| `PORT` | `u16` | `3000` | HTTP port for the API server |
| `HOST` | `string` | `0.0.0.0` | Host address to bind the API server to |
| `MAX_CONCURRENCY` | `usize` | `10` | Maximum number of concurrent task executions |

## Configuration Details

### PORT

The TCP port on which the Faber API server listens.

- **Type:** Integer (16-bit unsigned)
- **Range:** 1-65535
- **Default:** `3000`

**Example:**

```bash
PORT=8080 sudo ./faber
```

### HOST

The IP address to bind the server to. This controls which network interfaces accept connections.

- **Type:** String (IPv4 address)
- **Default:** `0.0.0.0` (all interfaces)

**Common Values:**

| Value | Description |
|-------|-------------|
| `0.0.0.0` | Listen on all available network interfaces |
| `127.0.0.1` | Listen only on localhost (local access only) |
| `192.168.1.100` | Listen on a specific IP address |

**Example:**

```bash
HOST=127.0.0.1 sudo ./faber
```

> **Security Note:** In production, you may want to bind to `127.0.0.1` and use a reverse proxy (like Nginx) for public access.

### MAX_CONCURRENCY

The maximum number of task executions that can run simultaneously. This helps control resource usage and prevents system overload.

- **Type:** Integer (unsigned)
- **Default:** `10`
- **Minimum:** `1`

**Example:**

```bash
MAX_CONCURRENCY=50 sudo ./faber
```

## Setting Environment Variables

### Temporary (Current Session)

Set variables inline with the command:

```bash
PORT=8080 HOST=127.0.0.1 MAX_CONCURRENCY=20 sudo ./faber
```

### Using export

Set variables for the current shell session:

```bash
export PORT=8080
export HOST=127.0.0.1
export MAX_CONCURRENCY=20
sudo ./faber
```

### Using .env File

Create a `.env` file in the working directory:

```bash
# .env
PORT=8080
HOST=127.0.0.1
MAX_CONCURRENCY=20
```

Then load it before running:

```bash
export $(cat .env | xargs) && sudo ./faber
```

### Using systemd

For a systemd service, use the `Environment` directive:

```ini
[Unit]
Description=Faber Task Execution Runtime
After=network.target

[Service]
Type=simple
User=root
Environment="PORT=3000"
Environment="HOST=0.0.0.0"
Environment="MAX_CONCURRENCY=50"
ExecStart=/usr/local/bin/faber
Restart=always

[Install]
WantedBy=multi-user.target
```

### Using Docker

Pass environment variables with `-e` or `--env-file`:

```bash
docker run --privileged --cgroupns=host \
  -p 3000:3000 \
  -e PORT=3000 \
  -e HOST=0.0.0.0 \
  -e MAX_CONCURRENCY=50 \
  custom-faber
```

Or using a docker-compose.yml:

```yaml
services:
  faber:
    image: custom-faber:latest
    ports:
      - "3000:3000"
    environment:
      - PORT=3000
      - HOST=0.0.0.0
      - MAX_CONCURRENCY=50
    privileged: true
    cgroupns: host
```

## Configuration Examples

### Development

For local development with lower concurrency:

```bash
PORT=3000 HOST=127.0.0.1 MAX_CONCURRENCY=5 sudo ./faber
```

### Production

For production with higher capacity:

```bash
PORT=3000 HOST=0.0.0.0 MAX_CONCURRENCY=100 sudo ./faber
```

### Behind Reverse Proxy

When running behind Nginx or another reverse proxy:

```bash
PORT=3000 HOST=127.0.0.1 MAX_CONCURRENCY=50 sudo ./faber
```

The reverse proxy would handle:

```nginx
server {
    listen 80;
    server_name faber.example.com;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## Troubleshooting

### Port Already in Use

If you see an error about the port being in use:

```bash
# Find what's using the port
sudo lsof -i :3000

# Either kill the process or use a different port
PORT=3001 sudo ./faber
```

### Host Binding Issues

If the server fails to start with a host-related error:

1. **Check if the IP is valid:** Ensure the `HOST` value is a valid IPv4 address
2. **Check permissions:** Some IP addresses may require specific privileges
3. **Use `0.0.0.0`:** This will bind to all interfaces as a fallback

### Concurrency Limits

If tasks are timing out or the system is slow:

1. **Reduce `MAX_CONCURRENCY`:** Lower values prevent resource exhaustion
2. **Monitor system resources:** Use `htop` or `top` to check CPU/memory
3. **Adjust based on workload:** Experiment to find the optimal value

## Default Configuration

If no environment variables are set, Faber uses the following defaults:

```rust
Config {
    port: 3000,
    host: "0.0.0.0",
    max_concurrency: 10,
}
```
