# Implementation Guide

This document provides a comprehensive overview of Faber's internal architecture, design decisions, and implementation details.

## System Architecture

### High-Level Overview

Faber is designed as a multi-layered secure execution runtime:

```
┌─────────────────────────────────────┐
│            HTTP API Layer           │  (faber-api)
├─────────────────────────────────────┤
│          Runtime Orchestrator       │  (faber-runtime)
├─────────────────────────────────────┤
│      Container & Resource Layer     │  (Linux namespaces + cgroups)
├─────────────────────────────────────┤
│         Linux Kernel APIs           │  (namespaces, cgroups v2, seccomp)
└─────────────────────────────────────┘
```

### Component Breakdown

#### 1. Runtime Engine (`faber-runtime`)

**Core Architecture:**
- **Runtime**: Main orchestrator managing task groups and resource allocation
- **TaskGroup**: Hierarchical task execution (sequential vs parallel)
- **Container**: Isolated execution environment using Linux namespaces
- **Cgroup**: Resource monitoring and limiting via cgroups v2

**Key Design Patterns:**

1. **Builder Pattern**: Extensive use for configuration objects
   ```rust
   let runtime = RuntimeBuilder::new()
       .with_max_concurrent_tasks(10)
       .with_default_timeout(Duration::from_secs(30))
       .build()?;
   ```

2. **Result Types**: Custom result types with detailed error information
   ```rust
   pub type RuntimeResult<T> = Result<T, RuntimeError>;
   
   #[derive(Debug, thiserror::Error)]
   pub enum RuntimeError {
       #[error("Container creation failed: {0}")]
       ContainerError(String),
       #[error("Resource limit exceeded: {}")]
       ResourceLimitExceeded(String),
       // ... detailed error variants
   }
   ```

3. **Async-Await**: Full async support using tokio runtime
4. **Resource Management**: RAII patterns for cleanup and resource tracking

#### 2. API Layer (`faber-api`)

**Core Components:**
- **Router**: Axum-based HTTP routing with `/api/v1` prefix
- **ExecuteHandler**: Handles task execution with file management
- **Cache**: DashMap-based request fingerprinting and response caching
- **State**: Shared application state with concurrency control
- **Middleware**: API key authentication and request processing

**Request Processing Flow:**

```
HTTP Request → Middleware → Router → Handler → Runtime → Response
     ↓             ↓          ↓         ↓         ↓
  Authentication   Routing   Validation Execution  Caching
```

## Container Implementation

### Namespace Isolation

Faber creates containers using multiple Linux namespaces:

```rust
// Container creation process
fn create_container(config: &ContainerConfig) -> RuntimeResult<Container> {
    let (container_pipe, host_pipe) = create_pipe_pair()?;
    
    match unsafe { fork() } {
        ForkResult::Child => {
            // In child process - setup isolation
            setup_namespaces(&config)?;
            drop_privileges(&config)?;
            execute_task(&config, container_pipe)?;
        }
        ForkResult::Parent { child } => {
            // In parent process - monitor and manage
            let container = Container::new(child, host_pipe, config.clone())?;
            Ok(container)
        }
    }
}
```

**Namespace Configuration:**
1. **PID Namespace**: Process isolation (container becomes PID 1)
2. **Mount Namespace**: Separate filesystem view
3. **Network Namespace**: Network stack isolation
4. **UTS Namespace**: Hostname and domain isolation
5. **IPC Namespace**: Inter-process communication isolation

### Mount Namespace Setup

```rust
fn setup_mount_namespace() -> RuntimeResult<()> {
    // Create minimal filesystem structure
    mount("proc", "/proc", "proc", MS_NOSUID | MS_NOEXEC | MS_NODEV, None)?;
    mount("tmpfs", "/tmp", "tmpfs", MS_NOSUID | MS_NODEV, None)?;
    
    // Bind mount essential devices
    mount("/dev/null", "/dev/null", "bind", MS_BIND | MS_NOSUID | MS_NODEV, None)?;
    mount("/dev/zero", "/dev/zero", "bind", MS_BIND | MS_NOSUID | MS_NODEV, None)?;
    mount("/dev/random", "/dev/random", "bind", MS_BIND | MS_NOSUID | MS_NODEV, None)?;
    mount("/dev/urandom", "/dev/urandom", "bind", MS_BIND | MS_NOSUID | MS_NODEV, None)?;
    
    Ok(())
}
```

### Privilege Dropping

```rust
fn drop_privileges(config: &ContainerConfig) -> RuntimeResult<()> {
    // Drop Linux capabilities
    drop_capabilities(&config.allowed_capabilities)?;
    
    // Set user/group IDs
    setresuid(config.uid, config.uid, config.uid)?;
    setresgid(config.gid, config.gid, config.gid)?;
    
    // Clear supplementary groups
    setgroups(&[])?;
    
    Ok(())
}
```

## Task Execution Model

### Task Group Processing

Faber supports hierarchical task execution:

```rust
pub enum ExecutionStep {
    Single {
        cmd: String,
        args: Option<Vec<String>>,
        files: Option<HashMap<String, String>>,
    },
    Parallel(Vec<ExecutionStep>),
}

pub enum TaskGroup {
    Sequential(Vec<ExecutionStep>),
    Parallel(Vec<ExecutionStep>),
}
```

### Execution Pipeline

```rust
impl Runtime {
    pub async fn execute(&self, group: TaskGroup) -> RuntimeResult<TaskGroupResult> {
        match group {
            TaskGroup::Sequential(steps) => {
                self.execute_sequential(steps).await
            }
            TaskGroup::Parallel(steps) => {
                self.execute_parallel(steps).await
            }
        }
    }
    
    async fn execute_parallel(&self, steps: Vec<ExecutionStep>) -> RuntimeResult<TaskGroupResult> {
        let mut tasks = Vec::new();
        
        for step in steps {
            let runtime = self.clone();
            let task = tokio::spawn(async move {
                runtime.execute_step(step).await
            });
            tasks.push(task);
        }
        
        let results = try_join_all(tasks).await?;
        Ok(TaskGroupResult { results, stats: calculate_group_stats(&results) })
    }
}
```

## API Server Implementation

### Request Caching

The API server implements intelligent request caching:

```rust
pub struct ExecutionCache {
    cache: Arc<DashMap<String, CachedResult>>,
}

impl ExecutionCache {
    pub fn get_or_execute<F, Fut>(&self, request: &ExecuteRequest, executor: F) -> impl Future<Output = RuntimeResult<TaskGroupResult>>
    where
        F: FnOnce(ExecuteRequest) -> Fut,
        Fut: Future<Output = RuntimeResult<TaskGroupResult>>,
    {
        let fingerprint = self.calculate_fingerprint(request);
        
        if let Some(cached) = self.cache.get(&fingerprint) {
            return async move { Ok(cached.result.clone()) }.left_future();
        }
        
        async move {
            let result = executor(request.clone()).await?;
            self.cache.insert(fingerprint, CachedResult::new(result.clone()));
            Ok(result)
        }.right_future()
    }
}
```

### Concurrency Management

```rust
pub struct AppState {
    pub runtime: Runtime,
    pub cache: ExecutionCache,
    pub semaphore: Arc<Semaphore>, // Controls concurrent executions
}

impl AppState {
    pub async fn execute_with_limit(&self, request: ExecuteRequest) -> RuntimeResult<TaskGroupResult> {
        let _permit = self.semaphore.acquire().await?;
        self.cache.get_or_execute(&request, |req| self.runtime.execute(req.into())).await
    }
}
```

## Security Architecture

### Defense in Depth

Faber implements multiple security layers:

1. **Process Isolation**: Linux namespaces
2. **Privilege Reduction**: Unprivileged user + capability dropping
3. **Resource Limits**: Cgroups v2 enforcement
4. **File System Restrictions**: Minimal mount namespace
5. **API Authentication**: Required API key validation
6. **Input Validation**: Request sanitization and validation

### Capability Management

```rust
pub const ALLOWED_CAPABILITIES: CapSet = capset![
    Cap::CAP_DAC_OVERRIDE,
    Cap::CAP_SETGID,
    Cap::CAP_SETUID,
];

fn drop_capabilities(allowed: &CapSet) -> RuntimeResult<()> {
    let mut caps = CapSet::get_proc()?;
    caps.clear();
    caps.extend(allowed.iter().copied());
    caps.set_proc()?;
}
```

### Resource Tracking

```rust
pub struct ResourceTracker {
    active_tasks: AtomicU64,
    total_memory_used: AtomicU64,
    peak_concurrent: AtomicU64,
}

impl ResourceTracker {
    pub fn task_started(&self) {
        let current = self.active_tasks.fetch_add(1, Ordering::Acquire);
        self.peak_concurrent.fetch_max(current + 1, Ordering::Release);
    }
    
    pub fn task_completed(&self, memory_used: u64) {
        self.active_tasks.fetch_sub(1, Ordering::Release);
        self.total_memory_used.fetch_add(memory_used, Ordering::Acquire);
    }
}
```

## Error Handling Strategy

### Error Taxonomy

```rust
#[derive(Debug, thiserror::Error)]
pub enum RuntimeError {
    // Container-related errors
    #[error("Container creation failed: {source}")]
    ContainerError { source: Box<dyn std::error::Error + Send + Sync> },
    
    // Resource management errors
    #[error("Resource limit exceeded: {limit} (current: {current})")]
    ResourceLimitExceeded { limit: String, current: String },
    
    // System call errors
    #[error("System call failed: {syscall} (errno: {errno})")]
    SystemCallError { syscall: String, errno: i32 },
    
    // Timeout errors
    #[error("Task execution timed out after {timeout_ms}ms")]
    TimeoutError { timeout_ms: u64 },
}
```

### Recovery Mechanisms

- **Graceful degradation**: Fallback to less restrictive limits when possible
- **Resource cleanup**: Automatic cgroup and namespace cleanup
- **State consistency**: Ensuring internal state remains consistent after failures
