# Getting Started

This guide will help you get Faber up and running on your system.

## Prerequisites

Faber runs on Linux systems and requires:

- **Linux Kernel**: 5.x or higher (for cgroups v2 support)
- **Docker**: For containerized deployment
- **Root privileges**: Currently required for creating device nodes

### System Requirements

- Minimum 2GB RAM
- 1 CPU core
- 500MB disk space

## Installation

### Option 1: Using Docker (Recommended)

The easiest way to run Faber is using Docker. First, create a custom Dockerfile that extends the base Faber image with your required compilers or interpreters:

```dockerfile
FROM vgfractal/faber AS faber
FROM debian:latest

# Install compilers and tools
RUN apt update && apt install -y \
    gcc \
    make \
    libc-dev \
    python3 \
    python3-pip \
    nodejs \
    npm

WORKDIR /opt
COPY --from=faber /opt/faber /opt

EXPOSE 3000/tcp
ENTRYPOINT ["./faber"]
```

Build the image:

```bash
docker build -t custom-faber .
```

Run the container:

```bash
docker run --privileged --cgroupns=host -p 3000:3000 custom-faber
```

> **Why `--privileged` and `--cgroupns=host`?**
> These flags are required for the container to create cgroups for resource isolation. Future versions will support rootless operation.

### Option 2: Building from Source

If you prefer to build Faber from source or want to contribute:

#### Prerequisites

- **Rust**: 1.70 or higher
- **Cargo**: Comes with Rust

#### Clone and Build

```bash
# Clone the repository
git clone https://github.com/Fractal-Tess/faber.git
cd faber

# Build the project
cargo build --release

# The binary will be at target/release/faber
```

#### Run the Binary

```bash
# Run with default settings (port 3000)
sudo ./target/release/faber

# Or with custom settings
PORT=8080 HOST=127.0.0.1 MAX_CONCURRENCY=20 sudo ./target/release/faber
```

## Configuration

Faber can be configured via environment variables:

| Variable | Default | Description |
|----------|---------|-------------|
| `PORT` | `3000` | HTTP port for the API server |
| `HOST` | `0.0.0.0` | Host address to bind to |
| `MAX_CONCURRENCY` | `10` | Maximum number of concurrent task executions |

### Example Configuration

```bash
export PORT=8080
export HOST=127.0.0.1
export MAX_CONCURRENCY=20

sudo ./target/release/faber
```

## Verifying Installation

Once Faber is running, verify it's working by checking the health endpoint:

```bash
curl http://localhost:3000/api/v1/health
```

**Expected Response:**

```json
{
  "status": "healthy"
}
```

## Your First Execution

Let's run a simple "Hello, World!" example to make sure everything works:

```bash
curl -X POST http://localhost:3000/api/v1/execute \
  -H "Content-Type: application/json" \
  -d '[
    {
      "cmd": "/bin/echo",
      "args": ["Hello, Faber!"]
    }
  ]'
```

**Expected Response:**

```json
[
  {
    "stdout": "Hello, Faber!\n",
    "stderr": "",
    "exit_code": 0,
    "stats": {
      "memory_peak_bytes": 524288,
      "cpu_usage_percent": 5,
      "pids_peak": 1,
      "execution_time_ms": 45
    }
  }
]
```

## A More Complex Example

Let's compile and run a C program:

```bash
curl -X POST http://localhost:3000/api/v1/execute \
  -H "Content-Type: application/json" \
  -d '[
    {
      "cmd": "/usr/bin/gcc",
      "args": ["hello.c", "-o", "hello"],
      "files": {
        "hello.c": "#include <stdio.h>\n\nint main() {\n    printf(\"Hello, World!\\n\");\n    return 0;\n}\n"
      }
    },
    {
      "cmd": "./hello"
    }
  ]'
```

This request:
1. Creates a `hello.c` file with a simple C program
2. Compiles it with `gcc`
3. Runs the compiled binary

**Expected Response:**

```json
[
  {
    "stdout": "",
    "stderr": "",
    "exit_code": 0,
    "stats": {
      "memory_peak_bytes": 5767168,
      "cpu_usage_percent": 16722,
      "pids_peak": 3,
      "execution_time_ms": 118
    }
  },
  {
    "stdout": "Hello, World!\n",
    "stderr": "",
    "exit_code": 0,
    "stats": {
      "memory_peak_bytes": 0,
      "cpu_usage_percent": 0,
      "pids_peak": 0,
      "execution_time_ms": 17
    }
  }
]
```

## Running in Production

### Docker Compose

For production deployments, consider using Docker Compose:

```yaml
version: '3.8'

services:
  faber:
    image: custom-faber:latest
    ports:
      - "3000:3000"
    environment:
      - PORT=3000
      - HOST=0.0.0.0
      - MAX_CONCURRENCY=50
    restart: unless-stopped
    # Required for cgroups
    privileged: true
    cgroupns: host
```

### Reverse Proxy

Place Faber behind a reverse proxy (like Nginx) for production:

```nginx
server {
    listen 80;
    server_name faber.example.com;

    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### Authentication

> **Important:** Faber does not include built-in authentication. For production use:
>
> - Place behind an authenticating reverse proxy
> - Use API Gateway services (AWS API Gateway, NGINX Plus, etc.)
> - Implement authentication middleware in a custom wrapper

## Troubleshooting

### Port Already in Use

If you see an error like `address already in use`, the port is already taken:

```bash
# Find what's using the port
sudo lsof -i :3000

# Either kill the process or use a different port
PORT=3001 sudo ./faber
```

### Permission Denied

Faber requires root privileges to create device nodes:

```bash
# Use sudo
sudo ./faber

# Or run as root user
su - ./faber
```

### Cgroups Issues

If you see cgroup-related errors:

```bash
# Check cgroups v2 is available
mount | grep cgroup

# Ensure cgroupns=host flag when using Docker
docker run --privileged --cgroupns=host ...
```

### Container Failures

If tasks fail to execute:

1. Verify required tools are installed in the container
2. Check the `stderr` field in the response
3. Ensure the `cmd` path is absolute
4. Verify file paths in `files` are correct
