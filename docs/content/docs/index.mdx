# Welcome to Faber

<img src="/faber.png" alt="Faber Logo" width="200" />

Faber is a **secure, sandboxed task execution runtime** that runs commands in isolated containers with resource limits and monitoring.

## What is Faber?

Faber provides a robust runtime environment for executing untrusted code safely. It combines Linux container technologies with resource monitoring to create a secure execution environment.

### Key Features

- **Container Isolation**: Uses Linux namespaces to isolate execution environments
- **Resource Limits**: Cgroups-based memory and CPU constraints
- **Security**: Runs as unprivileged user with dropped capabilities
- **Monitoring**: Tracks memory, CPU usage, process count, and execution time
- **Flexible Execution**: Support for sequential and parallel task execution
- **REST API**: Simple HTTP API for task submission and execution

## Architecture

Faber consists of several core components:

### Runtime

The runtime is responsible for:
- Creating isolated container environments using namespaces
- Enforcing resource limits via cgroups
- Managing task lifecycle (creation, execution, cleanup)
- Monitoring resource usage during execution
- Capturing stdout, stderr, and exit codes

**Progress:**

The REST API provides:

## Quick Start

### Using Docker

Create a Dockerfile that extends the base Faber image with your required compilers or interpreters:

```dockerfile
FROM vgfractal/faber AS faber
FROM debian:latest

# Install compilers
RUN apt update && apt install -y \
    gcc \
    make \
    libc-dev

WORKDIR /opt
COPY --from=faber /opt/faber /opt

EXPOSE 3000/tcp
ENTRYPOINT ["./faber"]
```

Build and run:

```bash
docker build -t custom-faber .
docker run --privileged --cgroupns=host -p 3000:3000 custom-faber
```

### Example: Running a C Program

Compile and execute a simple C program:

```c
// hello.c
#include <stdio.h>

int main() {
    printf("Hello, World!\n");
    return 0;
}
```

```bash
curl -X POST http://localhost:3000/api/v1/execute \
  -H "Content-Type: application/json" \
  -d '[
    {
      "cmd": "/usr/bin/gcc",
      "args": ["hello.c", "-o", "hello"],
      "files": {
        "hello.c": "#include <stdio.h>\n\nint main() {\n    printf(\"Hello, World!\\n\);\n    return 0;\n}\n"
      }
    },
    {
      "cmd": "./hello"
    }
  ]'
```

## API Overview

Faber exposes a simple REST API:

### Health Check

```bash
GET /api/v1/health
```

Returns the health status of the service.

**Response:**
```json
{
  "status": "healthy"
}
```

### Execute Tasks

```bash
POST /api/v1/execute
Content-Type: application/json
```

Execute a sequence or parallel group of tasks in isolated containers.

**Request Body:** An array of execution steps where each step is either:
- **Single Task**: An object with `cmd`, `args`, `env`, `stdin`, `files`, `working_dir`
- **Parallel Tasks**: An array of tasks to execute concurrently

**Response:** An array of execution results with stdout, stderr, exit codes, and resource statistics.

## Security Model

Faber implements multiple layers of security:

1. **Namespace Isolation**: Separate mount, network, PID, UTS, IPC namespaces
2. **Unprivileged User**: Tasks run as a non-root user
3. **Dropped Capabilities**: Linux capabilities are dropped to reduce attack surface
4. **Resource Limits**: Cgroups enforce memory and CPU constraints
5. **Timeouts**: Execution time limits prevent runaway processes

> **Note:** Currently requires root privileges to create device nodes. Future versions will support fully rootless operation.
