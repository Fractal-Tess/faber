# API Reference

The Faber API provides a simple REST interface for executing tasks in isolated containers. All endpoints accept and return JSON data.

## Base URL

```
http://localhost:3000
```

## Endpoints

### 1. Health Check

Check the service health status.

**Endpoint:** `GET /health`

**Request Parameters:** None

**Response:** `200 OK`

```json
{
  "status": "healthy"
}
```

**Example:**

```bash
curl http://localhost:3000/health
```

---

### 2. Execute Tasks

Execute a group of tasks in isolated containers. Tasks can be executed sequentially or in parallel.

**Endpoint:** `POST /execute`

**Content-Type:** `application/json`

## Request Format

The request body is an array of execution steps. Each step can be either:

### Single Task (Sequential)

A single task object that executes sequentially:

```typescript
{
  cmd: string,           // Command to execute (required)
  args?: string[],       // Command arguments (optional)
  env?: Record<string, string>,  // Environment variables (optional)
  stdin?: string,        // Standard input content (optional)
  files?: Record<string, string>, // Files to create (optional)
  working_dir?: string   // Working directory (optional)
}
```

### Parallel Tasks

An array of task objects that execute concurrently:

```typescript
[
  { cmd: string, args?: string[], ... },
  { cmd: string, args?: string[], ... }
]
```

## Request Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `cmd` | `string` | Yes | Absolute path to the command to execute |
| `args` | `string[]` | No | Arguments to pass to the command |
| `env` | `object` | No | Environment variables as key-value pairs |
| `stdin` | `string` | No | Content to write to the process's standard input |
| `files` | `object` | No | Files to create before execution (key: filename, value: content) |
| `working_dir` | `string` | No | Directory to execute the command in |

## Response Format

The response is an array of execution results, mirroring the request structure.

### Successful Task Result

```json
{
  "stdout": "string",
  "stderr": "string",
  "exit_code": 0,
  "stats": {
    "memory_peak_bytes": 1048576,
    "cpu_usage_percent": 15,
    "pids_peak": 5,
    "execution_time_ms": 1234
  }
}
```

### Failed Task Result

```json
{
  "error": "Error description",
  "stats": {
    "memory_peak_bytes": 0,
    "cpu_usage_percent": 0,
    "pids_peak": 0,
    "execution_time_ms": 0
  }
}
```

## Response Fields

| Field | Type | Description |
|-------|------|-------------|
| `stdout` | `string` | Standard output from the command |
| `stderr` | `string` | Standard error from the command |
| `exit_code` | `number` | Process exit code (0 = success) |
| `error` | `string` | Error message (present only on failure) |
| `stats.memory_peak_bytes` | `number` | Peak memory usage in bytes |
| `stats.cpu_usage_percent` | `number` | CPU usage percentage |
| `stats.pids_peak` | `number` | Peak number of processes |
| `stats.execution_time_ms` | `number` | Execution time in milliseconds |

## HTTP Status Codes

| Status | Description |
|--------|-------------|
| `200 OK` | Task executed successfully |
| `400 Bad Request` | Invalid request (e.g., empty task group) |
| `500 Internal Server Error` | Runtime or container setup failure |

## Examples

### Example 1: Simple Command

Execute a simple shell command:

```bash
curl -X POST http://localhost:3000/execute \
  -H "Content-Type: application/json" \
  -d '[
    {
      "cmd": "/bin/echo",
      "args": ["Hello, World!"]
    }
  ]'
```

**Response:**

```json
[
  {
    "stdout": "Hello, World!\n",
    "stderr": "",
    "exit_code": 0,
    "stats": {
      "memory_peak_bytes": 524288,
      "cpu_usage_percent": 5,
      "pids_peak": 1,
      "execution_time_ms": 45
    }
  }
]
```

### Example 2: Sequential Tasks

Compile and run a C program:

```bash
curl -X POST http://localhost:3000/execute \
  -H "Content-Type: application/json" \
  -d '[
    {
      "cmd": "/usr/bin/gcc",
      "args": ["-o", "hello", "hello.c"],
      "files": {
        "hello.c": "#include <stdio.h>\n\nint main() {\n    printf(\"Hello, World!\\n\");\n    return 0;\n}\n"
      }
    },
    {
      "cmd": "./hello"
    }
  ]'
```

**Response:**

```json
[
  {
    "stdout": "",
    "stderr": "",
    "exit_code": 0,
    "stats": {
      "memory_peak_bytes": 2097152,
      "cpu_usage_percent": 25,
      "pids_peak": 1,
      "execution_time_ms": 234
    }
  },
  {
    "stdout": "Hello, World!\n",
    "stderr": "",
    "exit_code": 0,
    "stats": {
      "memory_peak_bytes": 524288,
      "cpu_usage_percent": 5,
      "pids_peak": 1,
      "execution_time_ms": 12
    }
  }
]
```

### Example 4: With Environment Variables

Pass environment variables to the task:

```bash
curl -X POST http://localhost:3000/execute \
  -H "Content-Type: application/json" \
  -d '[
    {
      "cmd": "/usr/bin/env",
      "env": {
        "MY_VAR": "custom_value",
        "ANOTHER_VAR": "another_value"
      }
    }

```

Provide input via stdin:

[

      "cpu_usage_percent": 5,

### Example 6: Custom Working Directory

Execute command in a specific directory:

```bash
curl -X POST http://localhost:3000/execute \
  -H "Content-Type: application/json" \
  -d '[
    {
      "cmd": "/bin/pwd",
      "working_dir": "/tmp"
    }
  ]'
```

## Error Handling

### Empty Task Group

Request with an empty task array:

```bash
curl -X POST http://localhost:3000/execute \
  -H "Content-Type: application/json" \
  -d '[]'
```

**Response:** `400 Bad Request`

```json
{
  "error": "Empty task group"
}
```

### Container Setup Failure

If the container cannot be set up properly:

**Response:** `500 Internal Server Error`

## Caching

The API implements result caching. Identical task groups will return cached results without re-executing, improving performance for repeated operations.

## Security Considerations

- All tasks execute in isolated Linux containers
- Tasks run as an unprivileged user
- Resource limits are enforced via cgroups
- Only required capabilities are available
- Filesystem isolation prevents access to host resources
